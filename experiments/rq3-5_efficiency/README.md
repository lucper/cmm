# Research questions

- **RQ3:** How does our algorithm scale as $V$ (and thus $N$) grows?
- **RQ4:** How does our algorithm scale as $E$ grows?
- **RQ5:** How does our algorithm scale as the number $t$ of threads used increases?

## Prerequisites

Under the `experiments` directory:
1. Build the binaries by running `make -C src` (produces `bin/cmm_test`).
2. Run `./data/run.sh` to generate the artificial instances used for this experiment (see `experiments/README.md` for its options).

Python dependencies for plotting (`pandas`, `matplotlib`, `seaborn`) are listed
in `requirements.txt` and installed automatically into a local `venv/` on first
run.

## Usage

```bash
./run.sh [-P] -e <densities> -v <node counts> -x <taxid> -s <cutoff> -S <seed> \
         -p <P> -r <trials> -k <K> -l <ells> -E <density> -V <node count> -L <ell> -d <D>
```

The parameters used in the paper are:
```bash
./run.sh -e "05 10 15 20 25 30" -v "100 200 400 800 1600 3200" -x 9606 -s 700 -S 42 \
         -p 128 -r 1 -k 10000 -l "5 8" -E 05 -V 200 -L 8 -d 2
```

All options are required:

| Flag | Meaning |
|------|---------|
| `-e` | edge densities of the instances, in percent; RQ4 sweeps them |
| `-v` | node counts $V$ of the instances; RQ3 sweeps them |
| `-x` | taxid of the organism the instances were sampled from |
| `-s` | STRING combined score cutoff the instances were sampled with |
| `-S` | seed the instances were sampled with |
| `-p` | max number $P$ of threads; RQ3 and RQ4 use $P$, RQ5 sweeps $1, 2, 4, \dots, P$ |
| `-r` | number of trials per configuration |
| `-k` | number $K$ of top motif pairs kept by `cmm_test` |
| `-l` | motif lengths $\ell$ for RQ3 and RQ4; each runs with $d = 0, \dots, \ell-1$ |
| `-E` | edge density for RQ3 and RQ5 (one of `-e`) |
| `-V` | node count $V$ for RQ4 and RQ5 (one of `-v`) |
| `-L` | motif length $\ell$ for RQ5 (one of `-l`) |
| `-d` | number $d$ of wildcards for RQ5, in $[0,\ell)$ |
| `-P` | only concatenate and plot the existing measurements (stages 020 and 030) |

The densities, node counts, taxid, cutoff, and seed must match the instances generated by `../data/run.sh`.
RQ3 runs on the instances with density `-E` (one per node count), RQ4 on the instances with `-V` nodes (one per density), and RQ5 on the instance with `-V` nodes and density `-E`.

The experiment is a sequence of numbered `make` stages, each consuming the previous stage's output.
`run.sh` drives them in order:

| Directory | Produces |
|-----------|----------|
| `010-measure/` | One `cmm_test` measurement per file |
| `020-concat/` | One TSV per research question, with the measurements of the given parameters |
| `030-plot/` | The time and memory plots of each TSV |

## Files

| File / dir | Role |
|------------|------|
| `run.sh` | Driver: runs all stages in order. |
| `requirements.txt` | Python dependencies for `030-plot/plot.py`. |
| `<NNN>-*/` | The numbered pipeline stages, each with its own `Makefile`. |
| `030-plot/plot.py` | Renders a TSV into PDFs. |
| `<stage>/`, `010-measure/<instance>/` | Per-stage outputs (generated). |

## Output format

Filenames encode the full parameter set, so outputs from different parameters never collide.
A representative name, of a measurement in `010-measure/`:

```
<instance>/<instance>.l<L>d<D>.k<K>.p<threads>.trial<i>.perf
```

where `<instance>` is `sampled_<taxid>_s<cutoff>_S<seed>_V<V>_ed<NN>`, as generated by `../data/run.sh`.
`020-concat/` and `030-plot/` name their files after the parameters fixed for each research question.

Each row of the TSVs of `020-concat/` is one measurement (the one-line output of `cmm_test`) with the trial number prepended, tab-separated:

| # | Column | | # | Column | | # | Column |
|---|--------|-|---|--------|-|---|--------|
| 1 | `trial` | | 6 | `ell` | | 11 | `pruning_cnt` |
| 2 | `instance` | | 7 | `d` | | 12 | `num_threads_requested` |
| 3 | `edge_density` | | 8 | `max_rank` | | 13 | `num_threads_spawned` |
| 4 | `V` | | 9 | `min_rank` | | 14 | `time_ms` |
| 5 | `N` | | 10 | `avg_rank` | | 15 | `peak_ram_kb` |

Note that `num_threads_spawned` (13) may be lower than `num_threads_requested` (12).

## Plots

`030-plot/` writes the PDFs of each TSV as `<TSV name without .tsv>_*.pdf`. Time and memory are separate figures, with the legend saved as a standalone PDF.
The exact styling per RQ (log scaling, polynomial fits, `max_rank` annotations, RQ5 speedup labels) is set by the `plot.py` invocations in `030-plot/Makefile`.

The memory plots of RQ3 and RQ4 show the peak RAM **per thread**: `peak_ram_kb` (15), i.e. the peak resident set size of the whole process, divided by `num_threads_spawned` (13). This is set with the `--mem-per-thread` flag of `plot.py`.
The memory plot of RQ5 shows the **total** peak RAM, since it measures how memory grows with the number of threads.
